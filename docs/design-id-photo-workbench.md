## 1. 方案评估：独立页面 vs 子菜单

### 候选方案对比

| 维度 | A. 独立顶级页面（第三模式） | B. 子菜单入口 | C. 批量模式内工作台（推荐） |
|---|---|---|---|
| 认知负担 | 高：三模式并列，用户需理解差异 | 低 | 低：证件照本就是批量模板的分支场景 |
| 架构成本 | 高：裁切/变换/导出管线需重复接入 | 低 | 低：模板、构图、导出全复用 |
| 功能扩展空间 | 大 | 小 | 中（工具条 + 导出选项可承载） |
| 与"简洁"定位契合度 | 差 | 中 | 好 |

**结论：采用方案 C**——在照片批量模式中选择证件照类模板时，自动切换为「证件照工作台」视图（画布下方浮现背景工具条 + 导出面板出现排版选项）。不做第三模式，不做独立路由。

## 2. 功能边界

### 纳入（按优先级）

1. **背景色一键替换**（核心）：白 / 红（#D9001B）/ 蓝（#2D5AE1）预设 + 自定义取色
2. **边缘羽化调节**：滑块控制人像边缘过渡，防杂边
3. **打印排版导出**：6 寸相纸排版（一寸 8 张 / 二寸 4 张），300dpi
4. **头像构图辅助**：画布叠加证件照三分线/头顶距参考线

### 明确排除（与定位冲突）

- 美颜、磨皮、换装、AI 精修——超出"裁切工具"边界，且 AI 抠图违背零依赖原则
- 在线冲印对接——引入后端即失去纯本地说服力

## 3. 交互流程设计

```
导入照片 → 模板面板选「证件照」分组模板（如 一寸 295×413）
        → 画布进入工作台视图：
          · 下方浮现背景工具条：[白] [红] [蓝] [自定义] | 羽化 ━━━○━━
          · 画布叠加头像参考线（可开关）
        → 拖动/缩放构图（沿用现有手势）
        → 导出面板：格式 + [✓] 同时输出 6 寸排版
        → 导出（单张 → 文件；排版 → 1 张排版大图；多张 → ZIP）
```

流畅度要点：
- 选证件照模板**零额外点击**进入工作台（不需要用户找入口）
- 换色实时预览：预览在 1/4 分辨率上计算，<16ms/帧
- 背景色选择记忆到 localStorage（下次默认上次所用）

## 4. 技术实现建议

### 4.1 换底算法选型

| 方案 | 精度 | 依赖 | 结论 |
|---|---|---|---|
| HSV 魔棒（颜色容差替换 + 羽化） | 中（纯色背景证件照足够） | 零 | ✅ 一期采用 |
| face-api 语义分割 | 高 | 数 MB 模型 | 二期可选模块，默认关闭 |

实现要点：
- 采样四角像素估计背景色基准 → HSV 空间按容差生成 alpha 蒙版 → 高斯模糊蒙版边缘（羽化）→ 合成新背景色
-  Canvas ImageData 遍历， TypedArray 操作避免逐像素对象分配

### 4.2 性能

- 预览：最长边 1024 的缩略图上运算
- 导出：全分辨率一次运算；超 40M 像素沿用现有确认弹窗，二期再 Worker 化（REQ-012）

### 4.3 尺寸适配

- 证件照模板已带 mm+dpi 元数据，无需新增尺寸逻辑
- 排版输出：6 寸相纸 1800×1200px @300dpi，行列间距 2mm 出血

## 6. 与现有模块的架构关系

```
app.js / cropper.js（入口与视图切换）
   └─ 新增 bgreplace.js（SC.bgreplace：蒙版生成/换色/羽化，纯计算可单测）
        ├─ 输入：ImageData + 目标色 + 羽化半径
        └─ 输出：ImageData（不触碰 DOM，复用现有导出管线）
presets.js：模板对象新增 badge: 'id-photo' 标记（驱动工作台视图切换）
exporter.js：导出前调用 SC.bgreplace.apply()；排版器 layout.js 独立纯函数
```

数据流不变：构图状态（tx/ty/scale）与背景替换正交，导出时先变换合成、再换底、再 EXIF 移植。
