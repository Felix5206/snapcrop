## 📖 项目简介

证件照、报名照、签证照的处理长期依赖在线工具——照片要上传到别人的服务器，隐私与批量效率都不可控。简裁用浏览器原生 Canvas 把这件事搬回本地：

- **不上传** — 解码、裁切、编码全部在浏览器完成，没有后端，没有网络请求，可用 DevTools Network 面板自证。
- **不安装** — 零依赖单页应用，双击 `index.html` 即用，也可托管到任意静态服务器。
- **不降质** — 精准裁切按原图像素 1:1 输出，不重采样、不二次编码；导出完整保留 EXIF 元数据。

适合：教务 / 人事批量处理证件照、摄影工作室出片、社媒批量裁图，以及任何「不想把照片传给第三方」的场景。

## 🚀 快速开始

无需安装任何依赖，四种方式任选：

```bash
# 方式 1：直接打开（最简单）
# 双击 index.html（推荐 Chrome / Edge / Firefox 最新版）

# 方式 2：本地静态服务器（推荐，功能最完整）
python serve.py            # 默认 http://127.0.0.1:5173
npm start                  # 等价，调用上面的 python 脚本
npx --yes serve .          # 若机器上没有 Python

# 方式 3：Windows 安装版 / 便携版（免环境，适合分发）
# 安装版：运行 SnapCrop-Setup-x.y.z.exe（dist/ 或 Releases）——向导可自选安装路径，
#         创建开始菜单快捷方式与卸载程序，默认装到用户目录（免管理员权限）
# 便携版：双击 SnapCrop.exe——单文件免安装，内置完整运行时

# 方式 4：部署为静态站点
# 整个目录 push 到 GitHub Pages / Vercel / Netlify 即可，无需构建
```

重新打包：`npm run build:exe:win`（便携版单文件）或 `npm run build:installer`（安装向导，需 Inno Setup 6）。

> [!TIP]
> 💡 `file://` 协议下绝大多数功能可用，但部分浏览器会限制剪贴板与本地存储，开发时建议用方式 2。

## 🤔 两种模式的区别

| 维度 | 照片批量 | 精准裁切 |
| --- | --- | --- |
| **定位** | 流水线：把一堆照片统一成「指定规格」 | 精修：从一张照片里精确取出「一块区域」 |
| **输入 / 输出** | 多张进 → 单文件或 ZIP 出 | 单张进 → 单张出 |
| **输出尺寸** | 尺寸模板决定（如 25×35mm @300dpi → 295×413px） | 裁剪框决定（框多大就输出多大） |
| **是否重采样** | 是，图片按模板缩放 | 否，源矩形 = 目标矩形，1:1 拷贝原像素 |
| **适用场景** | 证件照批量出片、冲印、社媒裁图 | 取证截图、投稿裁剪、需保留原始像素的精修 |

二者输出语义不可互相替代（重采样 vs 1:1），因此保留两个入口；模板库共用同一数据源（`presets.js`）。

## 📋 使用流程

### 模式一：照片批量

1. **导入** — 点击「导入照片」或拖图进窗口（可多张混选）。
2. **选模板** — 右侧点选尺寸模板，或在「自定义尺寸」手动输入宽高与 DPI。
3. **调构图** — 拖动移动、滚轮缩放、滑杆旋转；点「应用到全部」同步所有照片。
4. **逐张复核** — 按 `Enter` 标记确认（列表出现绿点）。
5. **导出** — 点「批量裁切并导出」：1 张直接得到文件，多张自动打包 ZIP，原始 EXIF 完整保留。

### 模式二：精准裁切（原像素无损）

1. **选图** — 左侧点击或拖入单张（支持粘贴）。
2. **定尺寸** — 右侧设置裁剪框宽高（**单位即输出像素**），8 个控制点自由缩放，可锁定比例。
3. **定位** — 拖动裁切框移动位置；框外遮罩暗化，「框内效果」实时同步；边界约束保证框不出图、最小 16px。
4. **导出** — 点「确定并下载」，本地生成文件，不经过服务器、不改动原文件。

> [!IMPORTANT]
> 🔑 **无损原理**：`drawImage(源矩形, 目标矩形)` 两者尺寸恒等且关闭图像平滑，是原图像素的直接拷贝；PNG 无损输出，「沿用原格式」时 JPEG/WebP 用质量 1.0。

## ⚙️ 配置与自定义

模板三个层级，优先级从低到高：

1. **内置模板** — `assets/js/presets.js` 的 `SC.PRESETS` 数组，追加即生效：

   ```js
   { id: 'my-badge', name: '工作牌', group: '自定义', unit: 'mm', w: 54, h: 86, dpi: 300, desc: '胸牌内页' }
   ```

   `unit: 'mm'` 按 `dpi` 换算像素；`unit: 'px'` 直接使用 `w / h`。

2. **导入 JSON** — `config/presets.json` 是可导入的示例，界面「尺寸模板 → 导入」批量载入。
3. **我的模板** — 界面「保存为我的模板」写入 `localStorage`，不污染仓库代码。

**输出命名**支持变量：`{name}` 原文件名、`{preset}` 模板名、`{w}` `{h}` 输出像素、`{dpi}`、`{index}` 序号，默认 `{name}_{preset}_{w}x{h}`。

## 🧠 核心实现

- **变换模型**（`editor.js`）：所有变换在「输出像素坐标系」下定义，预览所见即导出所得。
- **铺满计算**：旋转后包围盒 `bw = iw·|cosθ| + ih·|sinθ|`，覆盖系数 `max(W/bw, H/bh)`；位移被 `clampOffset()` 夹紧，照片边缘永不进入裁切框。
- **EXIF 移植**（`metadata.js`）：Canvas 重绘会剥离元数据；导出时把源文件 EXIF/TIFF 块整块搬入新文件，仅改写像素尺寸与方向两个内联标签，失败时原样导出、绝不损坏图像。
- **ZIP 打包**（`zip.js`）：手写 ZIP 生成（store 零压缩 + CRC32），图片本身已压缩，避免引入外部依赖。
- **批量不卡顿**：逐张渲染、每张让出一帧，进度实时可取消。

## ❓ FAQ

**Q：照片会被上传到服务器吗？**
A：不会。没有后端，代码中不存在任何上传请求，DevTools Network 面板可自行验证。

**Q：导出的照片为什么比原图小？**
A：输出尺寸由模板决定（如 295×413）。需要更大的图请提高 DPI 或改用像素单位。

**Q：批量处理会卡死浏览器吗？**
A：不会。逐张渲染并让出主线程，进度实时可取消；上百张建议每批 ≤ 200 张。

**Q：EXIF 元数据会保留吗？**
A：会。导出时原始 EXIF（拍摄时间、设备型号、GPS 等）整块移植进导出文件，ZIP 解压后同样完整；源图无 EXIF（如截图）则正常输出不带元数据。

**Q：可以在公司内网部署吗？**
A：可以，整个目录即静态站点，复制到任意 Web 服务器即可，无需构建。

## ⚠️ 已知限制

- JPEG 导出为一次重编码，画质取决于质量参数；PNG / WebP 无损
- ZIP 打包为全量内存组装，数百张原图可能占较多内存（建议每批 ≤ 200 张）
- HEIC / HEIF 浏览器无法解码，需先转换为 JPG
- 自定义模板暂不支持界面内删除（可清空 localStorage 键 `snapcrop.customPresets.v1`）
- Windows 便携版为控制台程序（显示运行地址便于停止）；服务仅监听 127.0.0.1
